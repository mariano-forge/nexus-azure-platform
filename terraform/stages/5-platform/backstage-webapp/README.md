# Stage 5 — Platform (Backstage Web App)

> **Depends on:** Stage 0 (bootstrap), Stage 4 (observability).
> Provisions the Backstage self-service portal: App Service Plan, Container Registry, Key Vault, PostgreSQL Flexible Server, and the Web App itself.

## What it creates

| Resource | Name pattern | Purpose |
| --- | --- | --- |
| App Service Plan | `asp-<workload>-<env>` | Linux host for the Backstage container |
| Azure Container Registry | `acr<workload><env><4chars>` | Stores Backstage Docker images (suffix ensures global DNS uniqueness) |
| Key Vault | `kv-<workload>-<env>` | Application secrets — backend secret, GitHub token, DB password (see [ADR-009](../../../../docs/adr/009-key-vault-separation.md)) |
| PostgreSQL Flexible Server | `psql-<workload>-<env>-<4chars>` | Backstage catalog persistence (suffix ensures global uniqueness) |
| Web App (Linux container) | `app-<workload>-<env>` | Runs the Backstage container pulled from ACR |
| Key Vault secret | `postgres-password` | Auto-generated 32-char password, never set manually |

PostgreSQL credentials are injected into the Web App via **Key Vault references** — the password is never stored in plain text in App Service configuration.

## Prerequisites

1. **Stage `0-bootstrap` applied** — provides the remote backend.
2. **Stage `4-observability` applied** — provides the Log Analytics Workspace ID (`log_analytics_workspace_id` output).
3. **Docker image built and pushed to ACR** — see [backstage/README.md](../../../../backstage/README.md) for the build and push steps.
4. **Azure CLI** authenticated with `Owner` on the platform subscription:

   ```powershell
   az login
   az account set --subscription "<subscription-id>"
   ```

5. **Terraform ≥ 1.13** installed locally.

## Activate the remote backend

Uncomment the `backend "azurerm"` block in [terraform.tf](terraform.tf) using `0-bootstrap` outputs:

```powershell
cd ../../0-bootstrap
terraform output -json
```

```hcl
backend "azurerm" {
  resource_group_name  = "<output: resource_group_name>"
  storage_account_name = "<output: storage_account_name>"
  container_name       = "cntnr-tfstate"
  key                  = "platform.terraform.tfstate"
}
```

Then run:

```powershell
terraform init -reconfigure
```

## Usage

```powershell
cd terraform/stages/5-platform/backstage-webapp

# 1. Copy and fill in the variables
cp terraform.tfvars.example terraform.tfvars
#    Set platform_resource_group, platform_resource_group_id

# 2. Init with remote backend
terraform init

# 3. Review
terraform plan -out=tfplan

# 4. Apply
terraform apply tfplan
```

## After apply — required manual steps

The Web App starts but will crash until the Key Vault secrets are populated. Run these once:

```powershell
$KV = $(terraform output -raw keyvault_name)

az keyvault secret set --vault-name $KV --name "backend-secret" --value "<random-32-char-string>"
az keyvault secret set --vault-name $KV --name "github-token"   --value "<github-pat>"
# postgres-password is auto-generated by Terraform — no manual step needed

az webapp restart `
  --name "app-backstage-dev" `
  --resource-group "<platform_resource_group>"
```

> `postgres-password` is generated by `random_password` and stored in Key Vault automatically by `terraform apply` — do not set it manually.

## Outputs

| Output | Description | Consumed by |
| --- | --- | --- |
| `backstage_url` | Default hostname of the Web App | Backstage `APP_BASE_URL` config |
| `acr_login_server` | Full ACR login server URL | CI/CD image push (`docker push`) |
| `keyvault_name` | Name of the application Key Vault | Manual secret population (above) |
| `postgres_fqdn` | FQDN of the PostgreSQL server | `POSTGRES_HOST` env var (set automatically) |

## Upgrading the Backstage image

Build a new image via ACR Tasks (no Docker required locally), then re-apply:

```powershell
$ACR = $(terraform output -raw acr_login_server)

az acr build `
  --registry $ACR `
  --image backstage:v2 `
  --file ../../../../backstage/Dockerfile `
  ../../../../backstage/
```

Update `terraform.tfvars`:
```hcl
docker_image_name = "backstage:v2"
```

Then `terraform apply`.

## Troubleshooting

### Container fails to pull image — `ImagePullFailure`

**Symptom:** `Failed to pull image: <acr>.azurecr.io/backstage:latest:latest`

**Cause:** The AVM web site module appends `:latest` automatically. If `docker_image_name` already contains a tag (e.g. `backstage:v1`), the result is `backstage:v1:latest` which doesn't exist.

**Fix:** Never include a tag in `docker_image_name`. Use the bare image name and ensure the `:latest` tag exists in ACR:

```powershell
az acr import --name <acr-name> --source <acr>.azurecr.io/backstage:v1 --image backstage:latest --force
```

---

### Backstage crashes — `password authentication failed for user`

**Symptom:** All plugins fail with `error: password authentication failed for user "backstageadmin"`.

**Root cause:** The `POSTGRES_PASSWORD` Key Vault reference is not resolved — App Service passes the literal `@Microsoft.KeyVault(...)` string to the container.

**Diagnosis:**

```powershell
# 1. Check the Web App's managed identity has the role
$principalId = az webapp identity show --name <app-name> --resource-group <rg> --query principalId -o tsv
az role assignment list --assignee $principalId `
  --scope "/subscriptions/.../providers/Microsoft.KeyVault/vaults/<kv-name>" `
  --query "[].roleDefinitionName" -o tsv
# Expected: "Key Vault Secrets User"

# 2. Verify the secret exists
az keyvault secret show --vault-name <kv-name> --name postgres-password --query "{name:name,enabled:attributes.enabled}" -o table
```

**Fix:** If the role exists but resolution still fails, restart the Web App to force re-evaluation of Key Vault references. If that fails, inject the password directly as a temporary workaround:

```powershell
$pass = az keyvault secret show --vault-name <kv-name> --name postgres-password --query value -o tsv
az webapp config appsettings set --name <app-name> --resource-group <rg> --settings POSTGRES_PASSWORD="$pass"
```

> Remove the plain-text override with `terraform apply` once the KV reference issue is resolved.

---

### Backstage crashes — `KnexTimeoutError: Timeout acquiring a connection`

**Symptom:** Plugins fail with `KnexTimeoutError` instead of an authentication error.

**Cause:** The PostgreSQL Flexible Server firewall is blocking the connection. The App Service cannot reach the database.

**Fix:** Verify the firewall rule exists:

```powershell
az postgres flexible-server firewall-rule list `
  --name <postgres-server-name> `
  --resource-group <rg> `
  -o table
# Expected: AllowAllAzureServicesAndResourcesWithinAzureIps with 0.0.0.0 → 0.0.0.0
```

If missing, re-run `terraform apply` — the `azurerm_postgresql_flexible_server_firewall_rule` resource will recreate it.

---

### Key Vault reference — `invalid Key Vault secret name that can't be found`

**Symptom:** App Service reports a Key Vault reference error for a specific secret.

**Cause:** The secret doesn't exist in Key Vault (e.g. `github-token` was never created manually).

**Fix:** Create the missing secret:

```powershell
az keyvault secret set --vault-name <kv-name> --name "<secret-name>" --value "<value>"
az webapp restart --name <app-name> --resource-group <rg>
```

---

### App Service port mismatch — container times out on startup

**Symptom:** `Container did not respond to startup probe on port 80 within the expected time limit of 230s. Port mismatch detected: the container is listening on port 7007 but the platform is probing port 80.`

**Cause:** `WEBSITES_PORT` app setting is missing or incorrect.

**Fix:** Verify the setting is present:

```powershell
az webapp config appsettings list --name <app-name> --resource-group <rg> --query "[?name=='WEBSITES_PORT']"
```

If missing, re-run `terraform apply` — the `WEBSITES_PORT = var.app_port` setting will be restored.

---

### App is accessible but shows `404` on all routes

**Symptom:** The frontend loads (HTML served) but all routes return 404, including `/`.

**Cause:** Backend plugins are still initializing (Backstage can take 2-3 minutes on first start while it creates PostgreSQL schemas).

**Fix:** Wait 3-5 minutes after the warmup probe succeeds, then hard-refresh (`Ctrl+Shift+R`). Check live logs to confirm plugin initialization completed:

```powershell
az webapp log tail --name <app-name> --resource-group <rg>
# Wait for: "Plugin initialization complete"
```
